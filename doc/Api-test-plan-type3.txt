# 类型3接口测试计划

## 1. 背景说明

类型3接口是不含proApi但需调用proApi服务的接口。这些接口需要特殊处理，因为它们在URL中看似是普通接口，但在后端实现中需要调用proApi服务。

第二阶段的第4步要求我们实现类型3接口的处理，包括添加必要的认证逻辑、确保proApi调用正确以及实现令牌传递机制。本测试计划旨在验证这些修改的正确性。

## 2. 测试目标

1. 验证类型3接口能够正确使用Cookie进行用户身份验证
2. 验证类型3接口能够正确地将JWT令牌传递给proApi服务
3. 验证当JWT令牌过期或无效时能够正确处理错误
4. 验证类型3接口能够正确处理proApi服务响应
5. 验证性能和安全要求

## 3. 测试环境

- 本地服务：http://localhost:3000
- ProAPI服务：http://localhost:3002
- 测试账号：root/IloveGPT!

## 4. 测试接口清单

以下是需要测试的类型3接口：

1. 未读消息统计：`/api/support/user/inform/countUnread`
2. 系统插件模板：`/api/core/app/plugin/getSystemPluginTemplates`
3. 应用列表：`/api/core/app/list`
4. 钱包使用统计：`/api/support/wallet/usage/statistics`
5. 团队信息：`/api/support/user/team/info`

## 6. 验收标准

类型3接口实现应满足以下验收标准：

1. 所有基本功能测试用例通过
2. 认证机制正确工作，能够用Cookie验证用户身份
3. 能够正确从用户会话中获取JWT令牌并传递给proApi服务
4. 能够正确处理令牌无效或过期的情况
5. 能够正确处理proApi服务响应，包括错误处理
6. 响应时间在可接受范围内，不存在明显性能问题

## 7. 测试脚本

我们使用以下脚本来执行测试：

1. `test_type3_api.sh` - 专门测试类型3接口
2. `acceptance_test_phase2.sh` - 第二阶段综合验收测试

测试结果将保存在 `test_results` 目录中，以便后续分析和审查。

## 8. 总结

类型3接口的实现和测试是API认证机制修复的关键部分。通过本测试计划，我们能够全面验证类型3接口的认证逻辑、令牌传递机制和错误处理能力，确保API认证机制正确实现。
